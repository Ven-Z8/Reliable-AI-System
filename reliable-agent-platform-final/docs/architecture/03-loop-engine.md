# Loop Engineering

## Purpose

Run repeated valuable work without creating an unbounded autonomous process.

## Loop cycle

1. trigger;
2. discover work;
3. evaluate eligibility;
4. select one task;
5. prepare isolated workspace;
6. create run contract;
7. invoke harness;
8. independently verify;
9. request approval when required;
10. persist structured memory;
11. enter a named terminal state.

## Safety

- one mutation per repository;
- no autonomous merge;
- budgets cannot self-increase;
- memory cannot grant permissions;
- retries require progress potential;
- side effects are replay safe.
